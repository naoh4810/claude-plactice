# 交流会マッチングMCP（event-matching）

交流会の主催者が頭の中でやっている「この人とこの人をつなぎたい」を、申込フォームの**提供できること／探していること**から出す MCP サーバーです。
相性の良い組み合わせとその理由、ラウンドをまたいで同じ二人が重ならない**卓割り**、開催後の**紹介・フォロー**の材料までを返します。

## 役割分担

- **Claude** : 卓割りを表にする、声かけメモや「あらためてのご紹介」の文面を書く
- **このサーバー** : 申込一覧の取り込み、相性の判定と理由、卓割り、会った組の記録
- **主催者** : 当日の進行と、紹介文を送るかどうかの判断（送信はしない）

申込フォームで「紹介してもよい」と答えていない人は、**他の人の候補・紹介文の対象にしません**（本人には候補を出します）。同意の列が無い CSV は、全員を紹介しない扱いにします。

## ツール

| ツール | 内容 |
|---|---|
| `import_participants` | 申込フォームの CSV（UTF-8 / Shift_JIS）を取り込む。列名の揺れ（お名前／名前、提供できること／できること など）は自動で対応 |
| `participants` | 参加者の一覧（初参加・紹介の同意） |
| `suggestions` | 人ごとの「話すとよい相手」上位と理由。以前の会で会った相手は下げる |
| `unmatched_wants` | 誰とも結びつかなかった「探していること」。お客さん探し（顧問先、〜に困っている会社）と、参加者にいない相手を分ける |
| `table_plan` | 卓割り。同じ二人が二度同じ卓にならず、相性の合計が高く、初参加だけの卓ができないように配置 |
| `pair_detail` | 二人の情報とつながる理由（紹介文の材料） |
| `record_meetings` | 実際に同じ卓になった組を記録（次回以降は避ける） |
| `follow_ups` | 会った組のうち相性の良いもの（紹介・フォロー）と、会えなかった相性の良い組（次回つなぐ） |

プロンプト: `before_event`（卓割りの表・初参加の人への声かけメモ）、`after_event`（記録とフォローの文面）

## 相性の決め方

1. 「探していること」と「提供できること」を、言葉の一致か**テーマ**（撮影、ホームページ、SNS・LINE、税務・経理、不動産…）で突き合わせる。「集客」はホームページ・SNS・チラシで満たせる、とする
2. お互いに満たせる数がそのまま点数。初参加と常連の組は ＋0.5、同業は −0.5、以前会った組は −5
3. 「顧問先の紹介」「採用に困っている会社」のような**お客さん探し**は、同業者に当たってしまうのでテーマでは突き合わせず、`unmatched_wants` に回す（主催者の人脈でつなぐところ）

テーマと言葉は `matching.py` の `CONCEPTS` で足せます。

## デモの流れ（Claude Code で話しかける例）

架空の交流会（16人、うち初参加5人、紹介に同意していない人1人）で試せます。9月の会で同じ卓になった2組の記録も入っています。

1. 「10月の会の卓割りを、4人卓・3ラウンドで」→ 同じ二人が重ならない表と、卓ごとの注目の組み合わせ
2. 「初参加の人への声かけメモを」→ 千葉さん（農家）には「パン工房の木村さんと、仕入れと販路の話ができそう」など
3. 「個別につないだほうがいいものは？」→ 税理士・経理代行の「顧問先の紹介」、農家の「イベント出店先」など
4. 「終わったので記録して、フォローの文面を」→ 会えた組への紹介文（同意した人だけ）と、次回つなぐ候補

## 動かし方

```bash
pip install -r mcp/event_matching/requirements.txt

# サンプルで試す（変更はメモリ上だけ）
claude mcp add event-matching -- python mcp/event_matching/server.py

# 自分の交流会で使う（参加者と会った組の記録をファイルに保存。リポジトリの外に置く）
claude mcp add event-matching -e EVENT_DATA_PATH=/path/to/events.json -- python mcp/event_matching/server.py
```

| 環境変数 | 内容 | 省略時 |
|---|---|---|
| `EVENT_DATA_PATH` | 交流会ごとの参加者・卓割りと、会った組の記録を保存するファイル | サンプルをメモリ上で使う |

申込一覧は個人情報です。保存ファイルは主催者の手元に置き、メールアドレスや電話番号の列は取り込みません。

## テスト

```bash
pip install pytest
python -m pytest mcp/event_matching/test_server.py
```

`mcp/` 配下の各サーバーはモジュール名（`server` など）が同じなので、テストはサーバーごとに分けて実行してください。

## 制限

- 相性は言葉とテーマの突き合わせなので、「何をしている人か」の細かい相性（人柄、商圏）までは見ない。最後は主催者の判断
- 卓割りは山登り法なので、人数が多いと毎回少し違う配置になる（`seed` で固定できる）
- 同じ名前の参加者は区別できない（取り込み時に知らせる）
