# 交流会カレンダーMCP（event-calendar）

交流会の**予定を集め**、**行く会を選び**、参加した**成果を記録**して、続ける会・やめる会を決めるための MCP サーバーです（自分の営業用・A3）。
営業シートMCP（A1）が「会った人」の記録なのに対して、こちらは「会そのもの」の記録です。参加費と時間に対して面談・受注がどれだけ生まれたかを、会のシリーズ（毎月の朝活 など）ごとに見ます。

## 役割分担

- **Claude** : 告知文・チラシ・SNS の投稿・スクリーンショットから日時・会場・参加費・参加者層を読み取る。案を表にして見せる、ふり返りをまとめる
- **このサーバー** : 予定の保存（二重登録を防ぐ）、時間の重なり、シリーズごとの成果と見込み、.ics の読み書き
- **自分** : 行く会を決めて申し込む（このサーバーは申し込みをしない）

## ツール

| ツール | 内容 |
|---|---|
| `add_events` | 読み取った予定を登録。同じ日の同じシリーズは二重にせず、空いている項目だけ埋める |
| `import_ics` | connpass・Peatix・Google カレンダーの .ics を取り込む（日本時間・UTC・終日、折り返し行に対応） |
| `upcoming` | これからの予定と、時間が重なる予定・週ごとの申込済の数 |
| `recommend` | 候補の会を同じシリーズの過去の成果で並べ、重なり・週の上限を見て「行く案」を作る |
| `set_status` | 候補 / 申込済 / 見送り / 参加済 |
| `record_result` | 名刺・面談・受注・売上・費用・時間を記録 |
| `import_sheet_results` | 営業シート（交流会タブ）の CSV から、会ごとの名刺・面談・受注の**数だけ**を記録（名前は保存しない） |
| `pending_results` | 終わったのに成果を記録していない会 |
| `series_report` | シリーズごとの面談1件あたりの費用・時間と、続ける／様子見／見直しの目安 |
| `export_ics` | 申込済の予定を .ics に（Google カレンダーの「インポート」で取り込める） |

プロンプト: `plan_month`（告知の登録 → 記録漏れの確認 → 行く会の案 → 申込済にしてカレンダーへ）、`monthly_review`（シリーズごとのふり返りと来月の方針）

## 行く会の選び方

- シリーズは、タイトルから「vol.12」「第3回」「10月」「【満席】」などを落として決める（`series` で指定もできる）
- 見込み＝1回あたりの面談数。行ったことのないシリーズは 1回分「面談1」を足して数える（未経験は 1.0、3回で面談5なら (5＋1)/(3＋1)＝1.5）
- 見込みの高い順に、申込済の予定と時間が重ならない（会場が違えば移動30分を見る）・1週間の参加が上限以下、の会を「行く案」にする
- 見込みが 0.5 未満（何度か行って面談が生まれていない）のシリーズは選ばない

目安（`series_report`）: 2回以上行って面談0 → 見直し、売上が費用を超える か 面談1件あたり3,000円以下 → 続ける、それ以外 → 様子見。

## デモの流れ（Claude Code で話しかける例）

架空の交流会 15件（7〜9月に参加した7件と、これからの予定）、今日＝2026-10-02 で試せます。

1. 「記録してない会ある？」→ 9/30 の地域ビジネス交流会が申込済のまま
2. 「営業シートの CSV から数えて」→ `sample/営業シート_交流会タブ.csv` から名刺6・面談2 を記録（「知人の紹介」の行は対象外として返す）
3. 「これから行く会を決めたい」→ 朝活（過去3回で面談5）とミートアップが上位、同じ夜の懇親会は時間が重なるので見送り案、ランチ会は2回で面談0なので見送り案
4. 「このチラシの会も入れて」（画像や `sample/connpass_export.ics`）→ 登録、既にある会は二重にしない
5. 「ミートアップと AI 勉強会を申し込んだ。カレンダーに入れるファイルを」→ .ics を書き出し
6. 「これまでのふり返り」→ ランチ会は見直し、懇親会は面談1件6,000円で様子見

Google カレンダーの MCP（コネクタ）を使っている場合は、`export_ics` の代わりに Claude がそちらに直接予定を入れることもできます。

## 動かし方

```bash
pip install -r mcp/event_calendar/requirements.txt

# サンプルで試す（変更はメモリ上だけ）
claude mcp add event-calendar -- python mcp/event_calendar/server.py

# 自分の予定で使う（リポジトリの外に保存）
claude mcp add event-calendar -e EVENT_CALENDAR_PATH=/path/to/event_calendar.json -- python mcp/event_calendar/server.py
```

| 環境変数 | 内容 | 省略時 |
|---|---|---|
| `EVENT_CALENDAR_PATH` | 予定と成果を保存するファイル | サンプルをメモリ上で使う |
| `EVENT_CALENDAR_EXPORT_DIR` | `export_ics` の保存先 | `reports/` |

## テスト

```bash
pip install pytest
python -m pytest mcp/event_calendar/test_server.py
```

`mcp/` 配下の各サーバーはモジュール名（`server` など）が同じなので、テストはサーバーごとに分けて実行してください。

## 制限

- 予定を Web から自動で集めることはしない（告知文・画像・.ics をユーザーが渡す）。各サイトの利用規約に沿って、自分で見つけた告知を取り込む想定
- .ics のタイムゾーンは日本時間（Asia/Tokyo）と UTC のみ
- 見込みは面談の数だけで見ている。会った人の質（業種・決裁者か）は `memo` と営業シートで補う
