# 社内ナレッジ検索MCP（knowledge-search）

就業規則・マニュアル・FAQ などの社内資料フォルダを検索し、Claude が**出典付き**で答えられるようにする MCP サーバーです。
「社内の情報がどこにあるか分からない」「同じ質問に何度も答えている」という中小企業・総務部門向けのデモとして作りました。

- 回答には「どの資料のどこに書いてあるか」（見出し・ページ・行）を必ず付けさせる
- 資料に無いことは推測で補わず「記載がありません」と答えさせる
- 検索は手元のフォルダだけで完結。資料を外部の検索サービスや埋め込み API に送らない

## ツール

| ツール | 内容 |
|---|---|
| `list_documents` | 検索対象の資料一覧。読めなかった資料は理由付きで表示 |
| `search` | 質問文やキーワードで該当箇所を探す。資料のパス・位置・抜粋・スコアを返す |
| `read_section` | 該当箇所の全文を読む（見出しを指定すると配下の条文もまとめて返す） |

プロンプト: `answer_with_citations`（言い回しを変えて検索 → 全文で条件を確認 → 結論＋出典で回答 → 無ければ「記載なし」）

## 対応形式と出典の表し方

| 形式 | 出典の位置 | 必要なもの |
|---|---|---|
| Markdown（.md） | 見出しの階層（例: 第3章 休暇 > 第20条 年次有給休暇） | なし |
| テキスト（.txt） | 段落の開始行（例: 3行目）。FAQ の1問1答がそのまま出典になる | なし |
| PDF（.pdf） | ページ（例: p.3） | `pypdf` |
| Word（.docx） | 見出しスタイルの階層 | `python-docx` |

資料が追加・更新されると、次のツール呼び出しで自動的に検索対象を作り直します。

## デモの流れ（Claude Code で話しかける例）

架空の会社「サンプル精工」の規程集（`sample_docs/`）で試せます。

- 「有給は何日前までに申請すればいい？半日でも取れる？」→ 就業規則 第20条を出典に回答
- 「夜遅くなったらタクシー使っていい？」→ 経費精算マニュアル 3.2 を出典に、使える条件を回答
- 「ChatGPT に取引先の図面を入れていい？」→ 情報セキュリティ規程 第15条・第16条から「入力不可」と回答
- 「副業はしていい？」→ 資料に記載が無いことを伝え、関連する第30条（他社役員への就任）を添える

## 動かし方

```bash
pip install -r mcp/knowledge_search/requirements.txt

# サンプルの規程集で試す
claude mcp add knowledge-search -- python mcp/knowledge_search/server.py

# 自社の資料フォルダを検索する
claude mcp add knowledge-search -e KNOWLEDGE_DIR=/path/to/社内資料 -- python mcp/knowledge_search/server.py
```

共有ドライブ（Google ドライブ・OneDrive など）をパソコンに同期しているフォルダを `KNOWLEDGE_DIR` に指定すれば、そのまま検索対象になります。

## 検索のしくみ

日本語は単語の区切りが無いので、文章を2文字ずつ（「就業規則」→「就業」「業規」「規則」）に区切って照合し、BM25 という手法で順位を付けます。
「いい」「して」のような ひらがなだけの2文字は、どの文にも出てきて順位を乱すため使いません。見出しとファイル名も検索対象です。

言葉の言い換え（「ChatGPT」→「生成AI」など）は検索側では扱いません。代わりに Claude に言い回しを変えて複数回検索させています。

## テスト

```bash
pip install pytest
python -m pytest mcp/knowledge_search/test_server.py
```

`mcp/` 配下の各サーバーはモジュール名（`server` など）が同じなので、テストはサーバーごとに分けて実行してください。

## 制限

- スキャンした画像だけの PDF は文字を取り出せない（OCR 済みの PDF なら読める）
- Excel・PowerPoint は未対応
- 資料が数千ファイル規模になると、起動と更新時の読み直しに時間がかかる（その規模なら埋め込み検索への置き換えを検討）
