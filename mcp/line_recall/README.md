# LINE予約・配信MCP（line-recall）

予約台帳から**来院が途切れた人**を見つけ、LINE で送る再来院の案内を Claude が下書きし、**案内の効果を測る**ところまでを扱う MCP サーバーです。
「2回目の来院につながらない」「定期で来ていた人がいつの間にか来なくなる」という整体・歯科・サロン向けのデモとして作りました。

## 途切れの判定は「その人のペース」で

一律に「60日来ていない人」とすると、2週おきの人の離脱を見逃し、2か月おきの人を誤って追いかけてしまいます。
このサーバーは来院間隔の中央値をその人のペースとし、それと比べて判定します。

| 分類 | 判定 |
|---|---|
| 予約あり | 次の予約が入っている（案内しない） |
| 新規（2週間以内） | 初回から2週間以内（まだ様子を見る） |
| **2回目未来院** | 来院1回だけで、初回から14〜120日 |
| **途切れ** | 2回以上来ていて、ペースの1.5倍かつ+14日を超えて空いている |
| **休眠** | 最後の来院から180日以上（来院1回の人は120日超） |
| 通院中 | いつものペースで来ている |

太字の3つが案内の対象です。

## ツール

| ツール | 内容 |
|---|---|
| `overview` | 顧客数・直近30日の来院・分類ごとの人数・CSV で読めなかった行 |
| `segments` | 分類の判定のしかたと人数 |
| `recall_list` | 分類ごとの案内候補を優先順に。最近案内した人には印。文面のルールも一緒に返す |
| `customer_history` | 1人の来院履歴・ペース・キャンセル |
| `visit_stats` | 期間の来院数・新規・**2回目来院率**（初回から60日以内）・キャンセル率・週ごとの来院 |
| `export_list` | 案内候補を CSV に書き出す（最近案内した人は除く） |
| `record_message` | 案内を送ったことを記録 |
| `message_effect` | 案内ごとに、何人が30日以内に戻ったか。**案内しなかった同じ分類の人と比べる** |

プロンプト:

- `recall_campaign` : 分類を選ぶ → 対象を確認 → 一斉配信の文面を下書き（ルールを守る）→ CSV → 送ったら記録
- `monthly_review` : 来院の数字 → 案内の対象 → これまでの案内の効果 → 今月送る案内

文面のルール（`recall_list` が毎回返す）: 施術の効果をうたわない／責めたり急かしたりしない／予約のしかたを1つだけ書く／同じ人への案内は月1回まで／名前や来院履歴を一斉配信の本文に入れない。

## 効果の測り方

`message_effect` は「案内した人のうち何人戻ったか」だけでなく、**送った日に同じ分類だったのに案内しなかった人**が同じ期間にどれだけ戻ったか（baseline）も出します。
案内しなくても戻る人はいるので、baseline より高いかどうかで効果を見ます。人数が少ないうちは参考程度にしてください。

## デモの流れ（Claude Code で話しかける例）

架空の「サンプル整体院」（`sample_reservations.json`、59人・約1年分、今日＝2026-10-01）で試せます。

1. 「来院の状況は？」→ 案内の対象は30人（2回目未来院17・途切れ9・休眠4）。2回目来院率は29%
2. 「8月に送った案内は効いた？」→ 2回目未来院の6人に送って2人が戻った（33%）。送らなかった3人は0人
3. 「2回目未来院の人に送る文面を作って」→ ルールに沿った一斉配信の下書きと、対象者の CSV

## 動かし方

```bash
pip install -r mcp/line_recall/requirements.txt

# サンプルで試す
claude mcp add line-recall -- python mcp/line_recall/server.py

# 自分の店の台帳で使う（予約システムから CSV を書き出す。配信の記録はファイルに保存）
claude mcp add line-recall \
  -e RESERVATIONS_CSV=/path/to/予約台帳.csv \
  -e LINE_STATE_PATH=/path/to/line_recall_state.json \
  -- python mcp/line_recall/server.py
```

CSV は UTF-8（BOM 付き可）か Shift_JIS。列名はよくある呼び方を自動で対応づけます。

| 項目 | 認識する列名 |
|---|---|
| 日付（必須） | 日付・来院日・予約日・利用日・日時・予約日時・来店日 |
| 顧客ID（無ければ名前で代用） | 顧客ID・会員番号・お客様番号・患者番号・カルテ番号・顧客番号・ID |
| 名前 | 名前・氏名・お客様名・顧客名・患者名・お名前 |
| メニュー | メニュー・コース・施術内容・サービス |
| 担当 | 担当・担当者・スタッフ・施術者 |
| 状態 | 状態・ステータス・予約状況・来院状況（来院／予約／キャンセル／無断キャンセル。空なら来院） |

| 環境変数 | 内容 | 省略時 |
|---|---|---|
| `RESERVATIONS_CSV` | 予約台帳の CSV | サンプル |
| `LINE_STATE_PATH` | 配信の記録を保存するファイル | メモリ上だけ |
| `LINE_EXPORT_DIR` | `export_list` の保存先 | `reports/` |

予約台帳は個人情報です（歯科は診療情報も含みうる）。CSV と記録ファイルは店の中に置き、共有フォルダやリポジトリには置かないでください。

## テスト

```bash
pip install pytest
python -m pytest mcp/line_recall/test_server.py
```

`mcp/` 配下の各サーバーはモジュール名（`server` など）が同じなので、テストはサーバーごとに分けて実行してください。

## 制限

- LINE への配信そのものはしない（LINE公式アカウントや配信ツールで人が送り、`record_message` で記録する）
- `export_list` の CSV は配信ツールへの取り込み形式に合わせていない（ツールごとに違うので列を合わせる）
- 過去の時点の分類（効果測定の baseline）は、その時点で入っていた予約が分からないので、来院の記録だけで判定する
