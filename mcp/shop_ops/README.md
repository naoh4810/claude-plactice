# ECストア運用MCP（shop-ops）

Shopify ストアの売上・在庫・商品説明を、Claude に話しかけるだけで扱えるようにする MCP サーバーです。
個人で EC を運営している人の「毎週の数字確認」「在庫切れの見落とし」「商品説明を書く時間が無い」をまとめて引き受けるデモとして作りました。

## ツール

| ツール | 内容 |
|---|---|
| `shop_overview` | ストア名・通貨・商品数（状態別）と、集計の基準日 |
| `list_products` | 商品一覧（状態・価格・在庫・説明文の文字数） |
| `sales_report` | 期間の売上・注文数・客単価・販売個数、売れ筋、日別の売上、直前の同じ長さの期間との比較。キャンセル済みの注文は除く |
| `inventory_forecast` | 直近の売れ行きから「あと何日で在庫が切れるか」を予測し、在庫切れ → 要発注 → 余裕あり の順に並べる |
| `products_needing_description` | 説明文が短い商品を、直近でよく売れている順に（売れ筋から直すと効果が大きい） |
| `update_description` | 商品説明の更新。**`apply=true` を渡すまではストアを変えず、変更前後を見せるだけ** |

プロンプト:

- `weekly_report` : 今週の数字（前週比）・気づいたこと3点・今週やること、の週次レポート
- `improve_descriptions` : 説明文が薄い商品を売れ筋から順に。足りない情報はユーザーに質問し、推測で書かない → 変更前後を確認 → 了承した商品だけ反映

## デモの流れ（Claude Code で話しかける例）

架空の「サンプルサウナ用品店」（`sample_store.json`、商品8点・2か月分の注文56件）で試せます。

1. 「今週の売上どうだった？」→ 売上・注文数・客単価と前週比、売れ筋
2. 「在庫が危ない商品は？」→ ポンチョ（残り約10日）とアロマ白樺（残り約11日）が要発注
3. 「説明文が薄い商品を直したい」→ 売れ筋のアロマ白樺から、足りない情報を質問 → 下書き → 変更前後を確認 → 反映

## 動かし方

### 1. サンプルモード（認証なしですぐ試す）

```bash
pip install -r mcp/shop_ops/requirements.txt
claude mcp add shop-ops -- python mcp/shop_ops/server.py
```

サンプルは過去のデータなので、最後の注文日（2026-09-27）を「今日」として集計します。書き込みはメモリ上だけです。

### 2. 本番モード（自分のストアにつなぐ）

1. Shopify 管理画面の「設定」→「アプリと販売チャネル」→「アプリを開発」でカスタムアプリを作る
2. Admin API のスコープに `read_products` `write_products` `read_orders` `read_inventory` を付ける（60日より前の注文も集計するなら `read_all_orders` も）
3. アプリをインストールして、Admin API のアクセストークン（`shpat_` で始まる）を控える
4. 環境変数を付けて登録する

```bash
claude mcp add shop-ops \
  -e SHOPIFY_STORE_DOMAIN=<ストア名>.myshopify.com \
  -e SHOPIFY_ACCESS_TOKEN=<アクセストークン> \
  -- python mcp/shop_ops/server.py
```

| 環境変数 | 内容 | 省略時 |
|---|---|---|
| `SHOPIFY_STORE_DOMAIN` | `xxx.myshopify.com` | サンプルモード |
| `SHOPIFY_ACCESS_TOKEN` | カスタムアプリの Admin API アクセストークン | サンプルモード |
| `SHOPIFY_API_VERSION` | Admin API のバージョン | `2026-07` |

アクセストークンはストアを書き換えられる鍵です。リポジトリや共有フォルダに置かないでください。
まずは `write_products` を付けずに読み取りだけで試し、説明文の更新を使うときに追加するのが安全です。

## テスト

```bash
pip install pytest
python -m pytest mcp/shop_ops/test_server.py
```

本番クライアントは、偽の Shopify API を相手にテストしています（ページ送り、UTC の注文時刻をストアのタイムゾーンの日付に直す処理、API エラーの扱い）。
実際のストアへの接続は、まだ確認していません。最初に本番モードで使うときは、`shop_overview` と `sales_report` の数字を Shopify 管理画面の数字と見比べてください。

`mcp/` 配下の各サーバーはモジュール名（`server` など）が同じなので、テストはサーバーごとに分けて実行してください。

## 前提と制限

- 金額は注文の合計金額（税・送料・割引を反映した額）。売れ筋の金額は商品ごとの小計（割引前）
- 1商品あたりのバリエーション、1注文あたりの商品は、それぞれ先頭20件まで読む（API の1回あたりの負荷上限に収めるため）
- レビューへの返信は未対応（Shopify に標準のレビュー API が無く、レビューアプリごとに仕組みが違うため）
- 在庫は全ロケーションの合計。ロケーション別には見ない
