# Computer use デモ：ふるさと納税 返礼品の一括登録（ロケトク 亀山さん向け）

AIが**画面を見て、人と同じようにクリック・入力して**、返礼品登録シートの内容を2つのふるさと納税ポータルの管理画面に登録します。
APIや画面の内部構造は一切AIに教えていません。手がかりはスクリーンショットだけです。

> ポータルA・Bは**デモ用の架空の管理画面**です。実在するポータルサイトとは関係ありません。

## デモで見せられること

| 見せ場 | 何が起きるか | 亀山さんへのメッセージ |
|---|---|---|
| ① 複数ポータルへの転記 | シートを読み、掲載先（A／B／両方）に応じて、画面の作りがまったく違うA（1画面フォーム）とB（3ステップの申請画面）にそれぞれ登録する | ポータルが増えても、同じAIがそのまま対応できます |
| ② 3割ルールのチェック | 備前焼の行（寄付10,000円・調達4,000円＝40%）に気づいて**自分で止まり、担当者に確認する** | 「勝手に間違った登録をしない」仕組みです |
| ③ 不備データの確認 | トートバッグの行は寄付金額が空欄。推測で埋めず、担当者に聞いてから登録する | 判断が必要なところだけ人に回します |
| ④ 公開前の承認 | 下書き登録までは自動。**公開（審査申請）の直前に必ず人の了承を取る** | 取り返しのつかない操作は人が最終決定します |
| ⑤ 画面リニューアルへの追従 | `--layout v2` でポータルAの配色・項目の並び・ラベル・ボタン位置を変えても、そのまま登録できる | 従来型のRPA（決まった手順の記録・再生）は画面変更で止まりますが、AIは止まりません |

録画では、画面下部の字幕にAIの実況が出て、クリック位置には赤い波紋が表示されます。確認依頼は画面中央にポップアップで出ます。

## ファイル構成

```
furusato-cu/
├── agent.py          # Claude（Computer use）でブラウザを操作するエージェント本体
├── server.py         # 架空ポータルA・Bと返礼品シートを配信するローカルサーバー（標準ライブラリのみ）
├── data/sheet.json   # 返礼品登録シートの中身（ここを書き換えればデモデータを変えられる）
└── web/              # 画面（デモ用デスクトップ、シート、ポータルA、ポータルB）
```

## 動かし方

### 1. 準備（初回のみ）

```bash
cd demos/furusato-cu
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
playwright install chromium   # 手元のPCのみ。Claude Code のクラウド環境では不要
```

### 2. APIキーを設定

```bash
export ANTHROPIC_API_KEY=sk-ant-...   # https://console.anthropic.com で発行
```

### 3. 実行

```bash
python agent.py                    # 標準のデモ。確認依頼にはターミナルで回答する
python agent.py --auto-answer      # 確認依頼に想定回答で自動返答する（無人で録画したいとき）
python agent.py --layout v2        # ポータルAを「画面リニューアル後」の版にして実行（見せ場⑤）
python agent.py --headed           # ブラウザ画面を表示しながら実行する（手元のPCで商談中に見せるとき）
```

終わると `runs/日時/` に次のファイルができます。

- `demo.mp4`：操作の録画（そのまま商談や交流会で見せられます）
- `result.json`：AIの最終報告、使ったトークン数、各ポータルの最終状態

`--auto-answer` のときの想定回答は `agent.py` の `AUTO_ANSWERS` にあります（トートバッグは「17,000円で登録」、備前焼は「見送り」、公開は「了承」）。

画面だけを見たいときは `python server.py` で起動し、ブラウザで <http://127.0.0.1:8765/?caption=1> を開いてください（`&layout=v2` でリニューアル版）。

## 費用と時間の目安

- モデルは Claude Opus 5.5（`claude-opus-5-5`）。1回のデモで数十ターンの操作になり、費用は実行後にターミナルへ概算が出ます。
- 古いスクリーンショットはサーバー側の context editing（不要になった過去の画面を自動で間引く機能）で整理し、長い作業でも会話の文脈があふれないようにしています。
- 人が手で入れても数分の作業なので、デモは「速さ」より「**画面を見て判断している**」ことを見せるのが目的です。実案件では件数・ポータル数が増えるほど効いてきます。

## 実案件にするときの注意

- 本番のポータルを操作する前に、各ポータルの利用規約（自動操作の可否）を確認する
- ログインはAIにさせず、人がログインした状態のブラウザを使う。パスワードはAIに渡さない
- 実行環境は自治体・事業者の本番PCではなく、隔離した仮想環境にする
- 閲覧した画面に紛れ込んだ悪意ある指示に従ってしまうリスク（プロンプトインジェクション）があるため、公開・削除などの前には今回のように人の承認を挟む
