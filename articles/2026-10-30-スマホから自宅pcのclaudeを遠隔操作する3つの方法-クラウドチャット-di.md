# スマホから自宅PCのClaudeを遠隔操作する3つの方法（クラウドチャット／Dispatch／Remote Control）を整理してみた

「会社のPCでClaudeに作業を頼んだまま、現場に出てしまった」——そんな場面で、手元のスマホから続きを指示できないかを調べました。この記事は、Claudeをスマホから操作する3つのルートの違いと、どれを選べばいいかの判断基準を整理したものです（筆者は現時点では理解までで、本番運用の実績はまだありません）。

## なぜ調べたか：製造業の現場は「PCの前にいない時間」が長い

私の普段の仕事は製造業の現場です。ラインを見て回り、打ち合わせに出て、戻ってくるのは夕方。その間、デスクのPCでは資料づくりや手順書の整理をClaudeに頼んでいることがあります。

ところが現場で「あ、あの資料、あの観点も入れておきたい」と思いついても、PCに戻るまで何もできません。メモアプリに書き留めて、帰ってから入力し直す。この「思いついてから実行までのタイムラグ」が、地味に効率を落としていました。

スマホからそのまま指示できれば、移動時間が作業時間になります。そう思って調べ始めたのですが、結論から言うと「Claudeをスマホから操作する」には **目的別に3つの別々の仕組み** があり、ここを混同すると話が通じなくなります。

## 3つのルートの違い

### 1. claude.ai のチャット — 何もしなくてもスマホで続きが打てる

いちばん単純なルートです。ブラウザやアプリで使う claude.ai のチャットは、**処理がすべてAnthropic側のクラウドで動いています**。あなたのPCは、単に画面を表示しているだけです。

つまり、自宅PCのブラウザで開いていた会話は、同じアカウントでスマホからログインすれば、**そのまま続きを打てます**。「遠隔操作」ですらなく、最初からどこからでも同じものを見ているだけ、という理解が正確です。

- 対象：claude.ai の通常のチャット（Webアプリ／モバイルアプリ）
- 必要な準備：なし（同一アカウントでログインするだけ）
- できないこと：PC内のファイルを読む、ローカルのコマンドを実行する

ここが重要で、クラウドチャットは**あなたのPCの中には一切触れません**。「自宅PCのこのフォルダのファイルを整理して」は、このルートでは不可能です。

### 2. Dispatch — デスクトップアプリ側のClaudeに届ける

claude.ai のチャットではなく、**PCにインストールしたClaudeデスクトップアプリ**で作業している場合。こちらはPC側で動いている部分があるので、クラウドチャットと同じようにはいきません。

ここで出てくるのが **Dispatch** です。スマホ側から、デスクトップアプリで動いているClaudeに対して指示を送り届ける仕組み、という位置づけになります。

- 対象：デスクトップアプリ版のClaude
- イメージ：外出先から「デスクのアプリ宛に伝言を飛ばす」

### 3. Remote Control（`/remote-control`） — ローカルのClaude Codeにつなぐ

ターミナル（黒い画面のコマンド入力ツール）で動かす **Claude Code** を使っている場合は、また別です。Claude Codeは完全にあなたのPC上で動き、PC内のファイルを読み書きし、コマンドを実行します。クラウドにはいません。

これをスマホからつなぐのが **Remote Control** で、Claude Code のセッション内で `/remote-control` というスラッシュコマンド（`/`で始まる命令）を実行して接続を開く、という流れです。

- 対象：ローカルで動かしているClaude Code
- 入口：`/remote-control`
- 性質：PC内のファイル操作まで届く＝いちばん強力で、いちばん慎重さが要る

## 整理すると「Claudeがどこで動いているか」で決まる

3つの違いは、覚え方としてはこれだけです。

| 使っているもの | Claudeの実行場所 | スマホからの接続方法 |
|---|---|---|
| claude.ai のチャット | クラウド | 準備不要。ログインすれば続行できる |
| デスクトップアプリ | PC（アプリ内） | Dispatch |
| Claude Code | PC（ローカル環境） | Remote Control（`/remote-control`） |

「スマホからClaudeを操作したい」という一言には、この3つが混ざっています。自分がどれを指しているのかを先に決めないと、調べても噛み合いません。

## つまずいた点と解決

### つまずき1：「Claudeアプリ」という言葉が3つを指していた

最初、私は「Claudeはスマホでも使えるんだから、PCでやってる作業も当然スマホから続けられるだろう」と思っていました。実際、claude.aiのチャットはその通りです。

ところが、PCのフォルダを整理させるような作業はスマホから触れません。なぜかが分からず混乱しました。

**解決のきっかけは、「Claudeがどこで計算しているか」を分けて考えたこと**です。クラウドで動いているものはどの端末からでも同じものが見える。PC上で動いているものは、PCにつなぐ仕組みが別途必要になる。この一本の軸で見たら、3つのルートが存在する理由がすっきり理解できました。

### つまずき2：「全部Remote Controlでいいのでは」と思った

いちばん強力なRemote Controlを覚えておけば済むのでは、と考えましたが、これは対象が違います。Remote Controlは **Claude Codeのための仕組み** であって、デスクトップアプリやクラウドチャットには使いません。道具箱が3つに分かれている、と考えるのが正確です。

### つまずき3：セキュリティ面で手が止まった

ここは正直に書きます。Remote Controlは、スマホからPCのファイルやコマンドに届く仕組みです。便利さと裏返しで、**会社のPCで気軽に試していいものか判断がつかず、実践には進めませんでした**。

現時点での私の結論は「まず自分の私物PC・個人の作業で挙動を確かめ、会社の情報が入った環境に持ち込むのはその後」です。社内規程や情報システム部門の方針がある会社なら、確認が先になります。現場の安全確認と同じで、順番を飛ばさないほうが結局早いと考えています。

## 明日から使えるチェックリスト

実際に試す前に、この順で確認すると迷いません。

1. **自分がどのClaudeを使っているか確認する**
   - ブラウザで claude.ai → クラウドチャット
   - PCにインストールしたアプリ → デスクトップアプリ
   - ターミナルで `claude` と打って使っている → Claude Code
2. **クラウドチャットだけで足りないか考える**
   - 「文章を考える」「要約する」「案を出す」だけなら、スマホでログインすれば今日から解決します。追加の仕組みは不要です。
3. **PC内のファイルに触る必要があるか判断する**
   - 必要ないなら、2で終わりです。ここで止まれるケースはかなり多いはずです。
4. **必要な場合、対象に合った方法を選ぶ**
   - デスクトップアプリ → Dispatch
   - Claude Code → セッション内で `/remote-control`
5. **会社の端末・情報を扱う前に、社内ルールを確認する**
   - 外部から社内PCに接続する形になるため、情報システム部門への確認を先に。
6. **まず私物環境・差し支えのない作業で試す**
   - 挙動を自分の目で確認してから、業務に広げます。

## この学びが解決する実務課題

製造業の現場に限らず、中小企業の現場担当者は「PCの前にいない時間」が長い職種が多いはずです。訪問、現場巡回、移動。その間に思いついたことを、帰社後に思い出しながら入力し直す——この往復が、実はかなりの時間を食っています。

今回分かったのは、**その多くは「クラウドチャットにスマホからログインする」だけで片付く**ということです。文章を考える、箇条書きを整える、議事録の観点を出す。この手の作業に、DispatchもRemote Controlも要りません。

一方、「PCの中のファイルを実際に動かす」領域に踏み込むと、専用の仕組みとセキュリティの検討が必要になります。ここを分けて考えられるようになったことが、今回いちばんの収穫でした。

## まとめ

- Claudeをスマホから操作する方法は3つあり、「Claudeがどこで動いているか」で決まります。
- 文章作業が目的なら、claude.aiにスマホでログインするだけで今日から解決します。
- PC内のファイルに触るDispatch／Remote Controlは、社内ルール確認と私物環境での検証を先に行うのが安全です。
