# Claude Code × MCP連携で非エンジニアができるようになったこと──環境構築からGit・外部ツール接続まで

製造業の現場で働きながら、副業でAI導入の相談やAI研修を受けている立場から、実際に手を動かして詰まった箇所を含めて記録します。対象は「プログラミングは書けないが、ターミナル（黒い画面）は触ってみようと思える人」です。エンジニアでない人がClaude CodeとMCPを触るとき、最初にどこでつまずくのかを共有します。

## そもそもClaude CodeとMCPは何なのか

まず言葉を整理します。

- **Claude Code**：ターミナル（コマンドを打つ黒い画面）上で動くClaudeです。ブラウザのチャットと違い、**自分のPCのファイルを直接読んで、直接書き換えられる**のが最大の差です。「このフォルダのExcelを全部見て、項目のズレを一覧にして」と頼めば、実際にフォルダを開いて処理します。
- **MCP（Model Context Protocol）**：AIと外部のツールをつなぐための共通の規格です。乱暴に例えると**USBの規格**に近いものです。以前は「このAIとこのツールをつなぐ専用の配線」を都度作る必要がありましたが、MCP対応のツールなら設定ファイルに数行書くだけでClaudeから触れるようになります。

現場的な言い方をすると、チャットのClaudeは「机の上で相談に乗ってくれる人」、Claude Code＋MCPは「実際に工場の中に入って、機械や棚を触ってくれる人」です。この差が想像以上に大きい、というのが今回の一番の学びでした。

## 非エンジニアが最初にやるべき順番

順番を間違えると心が折れます。私は一度折れかけたので、遠回りに見えても以下の順を推奨します。

1. **作業用のフォルダを1つ作る**：デスクトップに `ai-test` のような空フォルダを作ります。いきなり本業の重要ファイルがある場所で始めないでください。
2. **Claude Codeをインストールする**：公式の手順に沿ってインストールします。前提としてNode.js（JavaScriptを動かす土台のソフト）が必要になるので、これも先に入れます。
3. **そのフォルダに移動して起動する**：ターミナルで `cd`（フォルダ移動のコマンド）を使って作ったフォルダへ移り、Claude Codeを起動します。
4. **まず「読むだけ」の作業をやらせる**：「このフォルダの中身を一覧にして」「このCSVの列名を教えて」など、**書き換えが発生しない指示**から始めます。
5. **Gitを入れる**：ここで初めてGit（ファイルの変更履歴を残す仕組み）を導入します。理由は後述しますが、これが安全装置になります。
6. **MCPで外部ツールをつなぐ**：ここまで問題なく動いてから、初めて外部連携に進みます。

ポイントは4と5です。多くの入門記事はいきなり「コードを書かせてみよう」と進みますが、非エンジニアにとって最初の壁は**AIの能力ではなく、自分が何をされているか分からない不安**です。読むだけの作業を10回ほどやって「こいつはフォルダの中身をちゃんと見ている」と体感してから進むほうが、結果的に速いです。

## Git連携で変わったこと

Gitは「変更履歴を全部残しておいて、いつでも前の状態に戻せる仕組み」です。エンジニア向けの道具だと思って避けていましたが、**Claude Codeを使うなら非エンジニアこそ入れるべき**だと考えを改めました。

理由はシンプルで、Claude Codeはファイルを実際に書き換えるからです。指示があいまいだと、意図しない箇所まで直してしまうことがあります。Gitを入れておけば、変更前の状態がすべて記録されているので、「さっきの変更を全部取り消して」で元に戻せます。

さらに実務で効いたのは、**Claude Code自身にGitの操作を任せられる**ことでした。コマンドを覚えていなくても、「今の変更内容を要約して、履歴に記録して」と日本語で頼めば、変更点を確認したうえで記録まで実行してくれます。自分でGitのコマンドを暗記する必要がありませんでした。

## MCPで外部ツールにつないでみる

MCPの設定は、基本的には**設定ファイルに接続先を書き足す**という作業です。Claude Codeの設定ファイルに、使いたいMCPサーバー（＝つなぎ先の窓口プログラム）の情報を追記し、Claude Codeを再起動すると認識されます。

つないでみて分かったのは、**「AIができること」より「AIに何を触らせるか」を設計するほうが本質**だということです。ファイル操作、Web検索、外部サービスへの接続と、つなげば何でもできてしまうぶん、権限の範囲を自分で決める必要があります。

現場で例えるなら、新人に工場のマスターキーを渡すかどうかの話に近いです。全部の部屋の鍵を渡せば作業は速いですが、事故ったときの範囲も広がります。私は当面、**業務データのコピーを置いた専用フォルダ**の中だけで動かす方針にしました。

## つまずいた点と解決

正直に書きます。動かないときの原因は、AIの側ではなく、ほぼ**自分の環境**でした。

**つまずき1：どこで動いているのか分からなくなった**

ターミナルに慣れていないと、「今、自分はどのフォルダにいるのか」を見失います。別の場所でClaude Codeを起動していて、「ファイルが見つかりません」と言われ続けました。

→ 解決策は、起動前に必ず「今いる場所」を確認する癖をつけることでした。作業フォルダのパス（住所）をメモ帳に控えておき、毎回コピペで移動するようにしたら、この手のエラーはほぼ消えました。

**つまずき2：MCPの設定を書き換えても反映されない**

設定ファイルを編集したのに、Claudeが「そのツールは使えません」と返してくる。設定内容を何度も見直しましたが原因が分からず、かなりの時間を溶かしました。

→ 原因は**再起動していなかった**ことでした。設定ファイルは起動時に読み込まれるため、編集しただけでは反映されません。設備の制御盤の設定を変えて電源を入れ直していないのと同じでした。以後、「設定をいじったら再起動」を鉄則にしています。

**つまずき3：AIの提案をそのまま受け入れてしまった**

Claude Codeは変更前に「こう直します」と提案してくれます。最初のうちは内容が読めないので、反射的に承認していました。結果、意図しないファイルまで整理されてしまい、慌てました。

→ 助かったのはGitを入れていたことです。履歴から元の状態に戻せました。以後は、**提案の中で「どのファイルに触るか」の行だけは必ず読む**ことにしています。中身のコードは分からなくても、ファイル名は読めます。それだけで事故はかなり防げます。

**つまずき4：指示があいまいで、余計なことをされる**

「このファイルを整理して」だけだと、AIは良かれと思って構造ごと作り替えます。

→ 「**触っていい範囲**」と「**やらないこと**」を先に書くようにしました。たとえば「Aフォルダの中だけを対象に、ファイル名の変更はしない。中身の重複行を削除するだけ」といった形です。現場の作業指示書と同じで、範囲と禁止事項を書くほうが結果が安定します。

## この学びが実務のどんな課題を解決するか

中小企業の現場でよくあるのは、「Excelが100個あって、様式がバラバラ」「日報が紙とデータで二重管理」といった、**システム化するほどではないが人手でやるには重い**作業です。この領域は、これまで外注すると見積もりが高く、社内でやると誰かの残業になっていました。

Claude Codeはこの層に効きます。ブラウザのチャットでは「ファイルを1個ずつコピペする」手間が発生しますが、Claude Codeはフォルダごと処理できます。専用システムを作らずに、その場限りの整理作業を片付けられるのが実務的な価値です。

## まとめ

Claude CodeとMCPは、AIを「相談相手」から「実際に作業する相手」に変える仕組みです。非エンジニアの壁は技術力ではなく、環境の把握と権限設計にあります。Gitを安全装置として先に入れ、読むだけの作業から慣らすのが、遠回りに見えて一番早い道でした。
