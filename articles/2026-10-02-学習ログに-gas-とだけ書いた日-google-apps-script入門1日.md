# 学習ログに「GAS」とだけ書いた日 ― Google Apps Script入門1日目の正直な記録

製造業の現場で働きながら、副業でAIコンサル・研修をしています。2026年4月22日の学習テーマは「GAS（Google Apps Script）」。インプット中心で、手は動かしました。ただ、この日の学習ログに私が残した文字は、たった3文字「GAS」だけでした。この記事は、非エンジニアがGASを触り始めた初日の記録と、そこで気づいた「学習ログの取り方」という地味だけど効く反省の共有です。これからGASや新しいツールを独学で始める、中小企業の経営者・現場担当者の方に向けて書きます。

## GAS（Google Apps Script）とは何か

GASは、Googleスプレッドシートやフォーム、Gmail、ドライブなどを**プログラムから操作できる仕組み**です。言語はJavaScriptベース。Excelでいう「マクロ（VBA）」のGoogle版、と考えるとイメージしやすいと思います。

実務的に大きいのは次の3点です。

- **インストール不要**：Googleアカウントがあれば、ブラウザだけで書いて動かせます。情シスに許可を取ってソフトを入れる手間が発生しません。
- **クラウド上で動く**：自分のPCを閉じていても、設定した時刻に自動実行できます（トリガー機能）。
- **他のGoogleサービスとつながる**：スプレッドシートの内容を元にメールを送る、フォームの回答を整形する、といった「サービスをまたぐ作業」が得意です。

私がAI活用の文脈でGASに注目しているのは、**AIが出した処理の骨組みを、実際に動く仕組みに落とし込む「受け皿」として軽い**からです。生成AIに「こういう処理をするコードを書いて」と頼んでも、動かす環境がなければ絵に描いた餅になります。GASは環境構築がほぼゼロなので、その壁が低い。これが初日に触ってみて一番納得した点でした。

## 初日に手を動かした最小ステップ

「GASを学ぶ」と言っても、初日にやることは驚くほど少ないです。実際に踏んだ手順を、再現できる粒度で書きます。

1. Googleスプレッドシートを新規作成する。
2. メニューの「拡張機能」→「Apps Script」を開く。別タブでエディタが立ち上がります。
3. 初期状態で `function myFunction() { }` という空の関数が入っています。この中に処理を書きます。
4. 動作確認用に、ログ出力を1行だけ書く。

```javascript
function myFunction() {
  Logger.log("hello");
}
```

5. 保存（Ctrl+S もしくはフロッピーアイコン）して、上部の「実行」をクリック。
6. **初回だけ、権限の承認を求められます**。「このアプリは Google で確認されていません」という警告画面が出ますが、これは自分で書いたスクリプトなので想定どおりです。「詳細」→「（プロジェクト名）に移動」→アカウント選択→「許可」と進みます。
7. エディタ下部の「実行ログ」に `hello` が出れば、環境は完成です。

ここまでで数分です。この「数分で動くところまで行ける」という体感が、初日に得られた一番の収穫でした。VBAのようにファイル形式やマクロ有効化で悩む場面がなく、**非エンジニアに最初に勧めるなら現実的な選択肢だ**という手応えがあります。

なお、この日はここから先、スプレッドシートのセルを読み書きする練習まで触れた程度で、業務に投入できる成果物はまだありません。初日としては正直にその範囲です。

## つまずいた点と解決：ログが「GAS」の3文字だった件

技術的な詰まりより、この日最大の失敗は**学習ログの粒度**でした。

後日この日の記録を見返したとき、残っていたのは「GAS」という3文字だけ。すると、こうなります。

- どのサンプルコードを写経したのか分からない
- 承認画面でどう進んだのか、手順を再現できない
- 「次に何をやるつもりだったか」が完全に消えている

結果として、**翌週また同じゼロ地点から始め直す**羽目になります。副業で学習時間を確保している身には、この重複がいちばん痛い。現場の仕事でいえば、作業日報に「加工」とだけ書いて帰るようなもので、後工程の自分が困るわけです。

解決策として、その後はログのフォーマットを固定しました。1分で書ける4項目です。

1. **やったこと**（操作レベルで。例：スプレッドシート→拡張機能→Apps Scriptで空関数を実行、承認を通した）
2. **動いた／動かなかった**（エラーメッセージは原文のままコピペ）
3. **次の一歩**（例：A1セルの値を読み取る `getRange` を試す）
4. **実務でどこに使えそうか**（思いつきで可。例：日次の生産数集計の転記）

ポイントは4番です。技術メモだけだと、学んだことが業務課題と結びつかないまま蒸発します。「使えそうな場所」を一行添えておくと、後から見返したときに**学習が提案ネタの在庫になる**のを実感しました。

## この学びが解決する実務の課題

中小企業の現場でよく見るのは、次のような作業です。

- 複数のスプレッドシートから数字を集めて、毎朝1枚の報告書に転記する
- フォームで集めた回答を手で並べ替えて、担当者にメールで配る
- 定時になったら決まった宛先に同じ形式の連絡を送る

いずれも「判断はいらないが、人がやると時間と転記ミスが発生する」タイプの仕事です。GASはまさにこの領域を狙えます。そして生成AIと組み合わせれば、**処理の骨格をAIに書かせて、自分は動作確認と修正に集中する**という進め方ができます。初日の段階で、その道筋が現実的だと確認できたことが収穫でした。

## 明日から使えるチェックリスト

GASを「とりあえず動くところまで」持っていくための、初日用チェックリストです。

- [ ] Googleアカウントでスプレッドシートを新規作成した
- [ ] 「拡張機能」→「Apps Script」でエディタを開いた
- [ ] `Logger.log("hello")` を書いて保存した
- [ ] 実行し、初回の権限承認（「詳細」→「移動」→「許可」）を通した
- [ ] 実行ログに文字が出るのを確認した
- [ ] 学習ログに「やったこと／動いた・動かなかった／次の一歩／実務での使いどころ」の4項目を書いた
- [ ] 自分の業務の中から「毎日・毎週、同じ形で繰り返している転記作業」を1つ書き出した

最後の項目が、次回の題材になります。

## まとめ

GASは環境構築がほぼ不要で、非エンジニアでも数分で「動く」ところまで到達できます。初日の実質的な失敗は技術面ではなく、「GAS」の3文字しか残さなかった学習ログの粒度でした。学習記録には必ず「次の一歩」と「実務での使いどころ」を添える――これだけで、学びが翌週にちゃんとつながります。
