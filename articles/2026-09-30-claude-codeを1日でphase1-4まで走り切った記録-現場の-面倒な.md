# Claude Codeを1日でPhase1〜4まで走り切った記録：現場の「面倒な作業」がどこまで自動化できたか

製造業の現場で働きながらAIコンサルと研修を副業でやっています。今回は「Claude Code」を使って、環境構築からMCP連携まで一気に実践した1日の記録です。プログラミングが本業ではない人が、業務のどこまでを自動化できるのか、実際に手を動かした範囲で正直に書きます。

## そもそもClaude Codeとは何か

Claude Codeは、ターミナル（黒い画面でコマンドを打つツール）上で動くAIアシスタントです。ChatGPTのようなチャット画面と違うのは、**自分のPCのファイルを直接読み書きできる**点にあります。

「このフォルダのCSVファイルを整形して」と指示すれば、実際にそのファイルを開いて処理して保存までやってくれる。ここが、コピペ往復が必要なチャット型AIとの決定的な違いです。

中小企業の現場で効いてくるのは、まさにこの部分です。日々発生する「Excelを開いて、並べ替えて、別の形式で保存して」という作業は、チャット型AIだと結局人間がファイルを行き来させる必要があります。Claude Codeはそこを飛ばせます。

## 1日で通したPhase1〜4の中身

今回取り組んだのは、段階的に難易度が上がる4つのフェーズです。実際にやった順番で並べます。

### Phase 1：環境構築とHTML/CSS生成

まず環境構築。ここが最初の関門でした（詳細は後述します）。

動き出してからは、HTML/CSSの生成を試しました。「こういうレイアウトのページを作って」と日本語で指示するだけで、ファイルが生成されてブラウザで確認できる状態になります。社内向けの簡易な案内ページや、研修資料の配布ページくらいなら、ここだけで十分実用になる感触がありました。

### Phase 2：ファイル処理の自動化

ここからが本命です。試したのは2つ。

**rekordbox のCSV変換**  
DJソフト「rekordbox」が出力する楽曲リストのCSVを、別の形式に変換する処理です。趣味の領域ではありますが、やっていることは製造業の「設備が吐き出すログCSVを、集計用のフォーマットに変換する」とまったく同じ構造です。

- 元のCSVの構造をClaude Codeに読ませる
- 「こういう列構成に変換して、この形式で保存して」と指示する
- 出力を確認して、ズレていれば「3列目は日付形式にして」と修正指示

この往復が、Excelの関数やマクロを書くより圧倒的に速い。マクロを書ける人でも、仕様変更のたびに書き直す手間を考えれば、こちらのほうが現実的です。

**スクリーンショットの一括整理**  
溜まりに溜まったスクショフォルダを、撮影日ごとにフォルダ分けして整理させました。「2024年以降のPNGだけ、年月フォルダに振り分けて」といった条件も日本語で通ります。

地味ですが、これは**現場の写真管理**にそのまま応用できます。設備点検の写真、不具合の記録写真を日付と工程でフォルダ分けする作業は、多くの現場で手作業のはずです。

### Phase 3：ドキュメントのテンプレート化

見積書と提案資料のテンプレートを作らせました。

ポイントは、一度作ったテンプレートを**Claude Codeに覚えさせた状態で運用できる**ことです。「前回の見積書のフォーマットで、今回はこの条件で作って」という指示が通る。毎回ゼロから書式を整える時間がなくなります。

副業でコンサルをしていると見積書作成が地味に時間を食うので、ここは即効性がありました。

### Phase 4：Reactダッシュボード・CRM構築、Git連携、MCP連携

一番重い部分です。

- **Reactダッシュボード**：データを可視化する画面を、Webアプリの形で生成
- **簡易CRM**：顧客情報を管理する仕組みの構築
- **Git連携**：ファイルの変更履歴を記録・管理する仕組みとの接続
- **MCP連携**：Claude Codeを外部のツールやデータソースにつなぐ仕組み

MCP（Model Context Protocol）は、AIを他のサービスと接続するための共通規格だと考えてください。これがあると、Claude Codeが自分のPCの中だけでなく、外部のデータにも手を伸ばせるようになります。

ここまで来ると「AIに作業を頼む」から「AIを社内システムの一部として組み込む」フェーズに入ります。中小企業がいきなりここを目指す必要はありませんが、**Phase 2の自動化が定着した先にこの世界がある**と知っておくのは意味があると思います。

## つまずいた点と解決

### 環境構築で止まる

これが最大の壁でした。ターミナルを普段使わない人間にとって、「どのコマンドをどこで打つのか」が分からない。エラーが出ても、その英語メッセージが何を言っているのか分からない。

解決法はシンプルでした。**エラーメッセージをそのままAIに貼り付けて聞く**。何をしようとしていて、どんなエラーが出たかを丸ごと投げれば、次の一手が返ってきます。自分で英語を読んで調べようとしないほうが、結果的に速かったです。

ここで諦める人が多いと思いますが、逆に言えば**環境構築さえ越えれば、あとは日本語で指示するだけ**です。壁は最初の1回だけでした。

### 指示が曖昧だと、意図しないものが出てくる

「いい感じに整理して」では、想定と違う結果になります。ファイル処理は特にそうで、「どこに」「どういう名前で」「元ファイルは残すのか」を書かないと、後から確認作業が発生します。

対策として、指示の型を決めました。

1. **入力**：どのフォルダの、どのファイルを対象にするか
2. **処理**：何をどう変換・整理するか
3. **出力**：どこに、どんな名前で保存するか
4. **制約**：元ファイルは消さない、上書きしない、など

この4点を書くようにしてから、やり直しが激減しました。

### いきなり本番データでやらない

ファイルを直接操作できるということは、**壊すこともできる**ということです。試すときは必ずコピーしたフォルダで実行する。これを徹底しないと、取り返しのつかないことになります。

Git連携を学んだのは、この不安への答えでもありました。変更履歴が残っていれば、おかしくなっても前の状態に戻せます。

## 明日から使えるチェックリスト

初めて触る人が、まず1週間で試すならこの順番を推奨します。

- [ ] **環境構築は「エラーを丸ごとAIに貼る」前提で始める**。自力解決を目指さない
- [ ] **最初の題材は「自分が一番めんどくさいと思っているファイル作業」にする**。CSV変換、フォルダ整理、リネームあたりが最適
- [ ] **必ずテスト用のコピーフォルダを作ってから実行する**
- [ ] **指示は「入力・処理・出力・制約」の4点セットで書く**
- [ ] **一発で完璧を狙わない**。出力を見て「ここだけ直して」と修正指示を重ねるほうが速い
- [ ] **うまくいった指示文はメモに残す**。次回はコピペで再利用できる
- [ ] **業務で使うならGit連携まで行く**。履歴が残る安心感は想像以上

## この学びが解決する実務の課題

中小企業の現場で一番多いのは、「誰か一人が手作業でやり続けている、地味で時間のかかる作業」です。CSVの整形、写真の仕分け、決まった書式の書類作成。どれも重要ですが、付加価値は生みません。

システム導入で解決しようとすると見積もりが出た時点で止まります。一方、Claude Codeは**その作業をやっている本人が、日本語で指示して自動化できる**。ここが本質的に違う点です。

今回1日でPhase1〜4まで通してみて、Phase 2（ファイル処理の自動化）だけでも、多くの現場では十分な費用対効果が出ると感じました。Phase 4のReactやMCPは、その先に興味が出たら進めばいい領域です。

## まとめ

環境構築さえ越えれば、あとは日本語で指示するだけで現場の面倒な作業は自動化できます。  
まず試すべきは、CSV変換やフォルダ整理といった「毎回やっている地味な作業」です。  
必ずコピーしたデータで試し、指示は「入力・処理・出力・制約」の4点セットで書いてください。
