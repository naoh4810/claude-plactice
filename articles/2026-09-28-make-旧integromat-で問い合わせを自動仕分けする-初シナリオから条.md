# Make（旧Integromat）で問い合わせを自動仕分けする：初シナリオから条件分岐までの実践ログ

「フォームに届いた問い合わせを、資料請求とそれ以外に分けて担当者にメールしたい」——中小企業でよくあるこの手作業を、ノーコード自動化ツール **Make** で組んでみました。この記事は、製造業の現場で働きながらAI・自動化の支援をしている私が、Makeの基本操作から条件分岐までを実際に手を動かして通した記録です。途中でハマった403エラーの解決までそのまま書きます。

## そもそもMakeとは何か、なぜ選んだか

Makeは、GoogleスプレッドシートやGmailなどのサービスを線でつないで処理を自動化するツールです。プログラミング不要で、画面上に「モジュール」と呼ばれる丸いアイコンを並べて線でつなぐだけで動きます。

現場目線で言うと、**搬送ラインを組むのに近い感覚**です。「どこから材料（データ）が来て」「どう加工して」「どこへ流すか」を並べるだけ。製造業の工程設計に慣れている人ほど、直感的に理解できるはずです。

今回のゴールはシンプルに2つ。

- Phase 1：とにかく1本、動くシナリオ（自動化の処理フロー全体のこと）を作る
- Phase 2：条件によって処理を分ける「分岐」を作る

## Phase 1：初シナリオ・Gmail送信・スケジュール実行

最初に作ったのは、**決まった時刻にGmailでメールを送るだけ**のシナリオです。実用性はほぼありませんが、「自分の操作でMakeが動いた」という感覚を掴むには十分でした。

手順は次の通りです。

1. Makeで新規シナリオを作成し、最初のモジュールにGmailの「Send an Email」を選ぶ
2. Googleアカウントとの「Connection（接続）」を新規作成し、認証する
3. 宛先・件名・本文を手入力して、右下の「Run once」で1回だけ実行する
4. 実際にメールが届くことを確認する
5. 画面左下のスケジュール設定（時計アイコン）で実行タイミングを指定し、シナリオをONにする

ポイントは **3の「Run once」**です。Makeはシナリオを保存しただけでは動かず、この手動実行でテストできます。いきなり自動実行をONにすると、間違った設定のまま大量にメールが飛ぶ事故が起きます。必ず手動テスト→本番ONの順番にしてください。

## Phase 2：Watch Rowsでスプレッドシートを監視し、データを渡す

次に、Googleスプレッドシートの「Watch Rows」モジュールを起点にしました。これは**シートに新しい行が追加されたのを検知して、その行の内容を後続モジュールに渡す**仕組みです。問い合わせフォームの回答が溜まるシートを想定しています。

ここで覚える必要があるのが「マッピング」です。Watch Rowsが取得した値には、シートの列に対応して`A`（タイムスタンプ）、`B`（氏名）、`C`（問い合わせ内容）のような名前が付きます。Gmailモジュールの件名欄をクリックすると、これらの項目が候補として出てくるので、クリックして差し込みます。

つまり、件名を

```
【新規問い合わせ】{{B}} 様
```

のように組み立てられる、ということです。手打ちの固定文と、シートから来る変動値を混ぜられるのがマッピングの肝で、ここを理解すると一気に応用が利きます。

## Router＋フィルターで「資料請求」と「一般問い合わせ」を振り分ける

本題の条件分岐です。Makeでは **Router（ルーター）** というモジュールを挟むと、そこから処理の道が複数本に枝分かれします。分岐先のそれぞれの線に「フィルター」という条件を設定し、条件に合ったデータだけがその道を進みます。

今回設定したのはこの2ルートです。

- ルート1：問い合わせ内容が「資料請求」を **含む（Contains）** → 資料送付担当宛のメール
- ルート2：問い合わせ内容が「資料請求」を **含まない（Does not contain）** → 一般問い合わせ担当宛のメール

重要なのは、**ContainsとDoes not containを対にして両方を明示的に書く**ことです。片方しか条件を書かないと、条件から外れたデータが行き場を失い、どこにも通知されず黙って消えます。現場で言えば「NG品の排出口はあるのに、OK品の出口を作っていない」状態です。

検証も両方やりました。テスト用にシートへ「資料請求をお願いします」という行を追加して実行し、資料送付ルートだけが緑色に点灯することを確認。続けて「見積もりについて」という行で実行し、今度は一般問い合わせルートだけが動くことを確認。**両パターンとも実際にメールが届くところまで見て初めて「できた」と判断**しています。

## つまずいた点と解決

### 403エラー：「権限はあるのに動かない」

最大の詰まりどころがこれでした。Gmailモジュールを実行した瞬間に **403エラー** が出て止まる。Googleアカウントの認証は通っているし、自分のアカウントには当然メール送信権限があります。それなのに動かない。

原因は **スコープ（権限の範囲）** でした。OAuth認証では、「ログインできる」ことと「そのアプリがメール送信してよい」ことは別管理です。接続を作ったときに、メール送信に必要な権限にチェックが入っていない、あるいは許可されていない状態だと、認証自体は成功しているのに実行時だけ403で弾かれます。

解決の手順はこうです。

1. エラーメッセージを最後まで読む（どの権限が足りないかが書かれている）
2. Makeの該当モジュールの接続を一度削除、または「Add」で作り直す
3. 再認証の画面で、求められている権限のチェックを**すべて**入れる
4. Googleアカウントの「セキュリティ」→「サードパーティ製アプリとの連携」で、Makeに必要な権限が付いているか確認する
5. 再度Run onceで実行

教訓は、**認証エラーは「もう一度つなぎ直す」が最短ルート**だということ。設定画面をあれこれ触るより、接続を作り直したほうが早い場面が多いです。

### 「保存したのに動かない」

シナリオを保存しただけで満足して放置し、何も起きないと悩んだ時間がありました。Makeは左下のトグルを**ON**にして初めて自動実行されます。あわせて実行間隔（15分ごとなど）の設定も必要です。初歩ですが、最初は確実に一度やります。

## 明日から使えるチェックリスト

- [ ] まずは「Gmailで自分宛に1通送るだけ」のシナリオを作り、Run onceで動かす
- [ ] 認証エラー（403など）が出たら、設定をいじる前に接続を作り直して権限を全部許可する
- [ ] 起点をWatch Rowsにして、テスト用スプレッドシートを1枚用意する（本番データは使わない）
- [ ] 件名や本文に、シートの列の値をマッピングで差し込んでみる
- [ ] Routerを挟み、ContainsとDoes not containを**対で**設定する
- [ ] 分岐は必ず**全パターン**テストする（片方だけ見て終わらない）
- [ ] テストが全部通ってから、最後にスケジュール実行をONにする

## まとめ

Makeの条件分岐は、「振り分けて通知する」だけで人の確認作業を確実に減らせます。詰まる場所は機能そのものより認証（スコープ）で、接続を作り直せば大抵抜けられます。まずは自分宛にメールを1通、そこから分岐を1本増やす——この順番が一番速いです。
