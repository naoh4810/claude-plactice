# Claude Codeのルーティン機能で「月曜ブリーフィング」を自作した話──Gmail自動仕分けとセットで週次の情報整理を自動化

毎週月曜の朝、メールの山を眺めて「今週なにから手をつけるか」を決めるのに30分かかる。そんな状態を変えたくて、Claude Codeのルーティン（定期実行）機能で自分専用の週次ダッシュボードを組みました。この記事は、製造業の現場で働きながらAI研修を副業でやっている筆者が、実際に手を動かして構築した記録です。プログラマー向けではなく、「自分の仕事の段取りをAIに任せたい人」向けに書きます。

## 何を作ったのか：月曜ブリーフィングという名の週次ダッシュボード

作ったものはシンプルです。毎週月曜に、以下の3つが自動で1枚のレポートにまとまって出てくる仕組みです。

- **週次リサーチ**：自分の関心領域について、直近1週間の情報を拾ってまとめる
- **週次メール整理**：溜まったメールを分類し、対応が必要なものを洗い出す
- **学習目標の提示**：今週なにを学ぶか、直近の状況を踏まえて提案させる

ポイントは「Claudeに毎回お願いする」のではなく「Claudeが勝手に走る」状態にしたことです。Claude Codeにはルーティン（決まったタイミングで決まった作業を実行させる機能）があり、ここに手順書を登録しておけば、こちらが何もしなくても月曜の朝には結果が用意されています。

そして今回、もうひとつ並行して整備したのがGmailの自動仕分けです。これが実は肝でした。理由は後述します。

## 手順1：まず「人間がやっていること」を文章に書き出す

いきなりAIに指示を書こうとすると必ず失敗します。筆者も最初、いきなりプロンプト（AIへの指示文）から書き始めて手が止まりました。

順番はこうです。

1. **月曜の朝に自分が実際にやっている作業を、箇条書きで全部書き出す**
   例：「未読メールをざっと見る」「返信が必要なものを頭の中でリストアップ」「業界ニュースを3サイトくらい巡回」「今週やることをメモに書く」
2. **それぞれについて「判断基準」を言語化する**
   例：「返信が必要」とは何か？　→「差出人が取引先か社内の上長で、質問文が含まれているもの」
3. **AIに任せる部分と、自分が判断する部分を線引きする**
   情報の収集・分類はAI、最終判断は自分。ここを曖昧にすると、出力を信用できなくなります。

この「判断基準の言語化」が、結果的に一番価値のある作業でした。自分が無意識にやっていた選別を言葉にすると、AIに渡せるだけでなく、後からGmailのフィルタ条件にもそのまま転用できます。

## 手順2：Claude Codeのルーティンに手順書として登録する

書き出した内容を、Claudeへの指示文にまとめます。コツは「レポートの型」まで指定してしまうことです。

指示文に必ず入れた要素は次の4つです。

- **役割**：「あなたは私の週次アシスタントです」
- **入力**：何を見て判断するか（メールの受信箱、指定したリサーチ対象のテーマ）
- **出力の型**：見出しの構成を固定する。例「①今週の重要トピック3件 ②要対応メール一覧 ③今週の学習テーマ1つ」
- **禁止事項**：「推測で情報を補わない」「該当がなければ『なし』と書く」

特に最後の「該当がなければ『なし』と書く」は必須でした。これを入れないと、AIは無理やり何かを書こうとして、中身の薄い項目が並びます。

出力の型を固定するメリットは、毎週同じフォーマットで届くので、差分がすぐ分かることです。先週と見比べて「この案件、2週続けて未対応だな」と気づけるようになります。

## 手順3：Gmailの自動仕分けフィルタとラベル運用を整える

ここが今回の構築で一番効いた部分です。

メール整理を自動化しようとしたとき、最初はClaude側だけで何とかしようとしていました。しかし受信箱がぐちゃぐちゃのままだと、AIに渡す情報自体がノイズだらけで、出力の質が上がりません。**入力が汚れていると、どんなに指示を工夫しても出力はきれいになりません。**

そこでGmail側にフィルタを作り、受信時点で自動的にラベル（メールに付ける分類タグ）が付くようにしました。設計の方針は次のとおりです。

- **ラベルは多く作りすぎない**。最初は5つ程度に絞る（例：要対応／情報のみ／請求・契約／メルマガ／社内）
- **フィルタ条件は「差出人ドメイン」を軸にする**。件名のキーワードより誤爆が少なく安定します
- **メルマガ系は受信トレイをスキップ**して直接ラベルへ。受信箱に残すものを減らすのが目的です
- **迷ったら「受信箱に残す」側に倒す**。見落としのほうが痛いので、最初は緩めに設定します

ラベルが整うと、Claude側の指示も「『要対応』ラベルの付いたメールだけを対象に」と書けるようになり、一気にシンプルになります。AIに賢く判断させるより、**手前で機械的に絞り込んでからAIに渡す**ほうが確実で速い、というのが実感でした。

## 手順4：設定内容をNotionに保存する

作ったフィルタ条件と、Claudeに渡した指示文は、すべてNotionの1ページにまとめて保存しました。地味ですが、これをやらないと確実に後悔します。

保存した項目は以下です。

- ラベルの一覧と、それぞれの定義（どういうメールをここに入れるか）
- フィルタの条件（差出人ドメイン、キーワード、アクション）
- Claudeに登録した指示文の全文
- 変更履歴（いつ、何を、なぜ変えたか）

理由は単純で、**2週間後の自分は設定した理由を覚えていないから**です。「なぜこのドメインを除外したんだっけ？」となったとき、履歴があれば数秒で思い出せます。研修で人に説明するときの教材にもそのまま使えます。

## つまずいた点と解決

**つまずき1：指示文だけを作り込んで、入力側を放置していた**

最初はプロンプトの書き方ばかり調整していました。表現を変えても出力が安定しない。原因は指示文ではなく、受信箱が未分類のままだったことです。Gmailのフィルタを先に整えたら、同じ指示文でも出力が見違えました。**AIの精度が出ないとき、疑うべきは指示文より入力データ**です。

**つまずき2：ラベルを細かく作りすぎた**

最初は10個以上のラベルを設計しようとして、条件が重なり合って手が止まりました。1通のメールがどのラベルに入るべきか自分でも判断できない。結局5つ程度に絞り、「まずは粗く分けて、運用しながら足す」方針に切り替えました。分類は細かくするほど正確になるように思えますが、実際は**維持できない分類は機能しない**だけです。

**つまずき3：AIが空欄を埋めようとして冗長になる**

該当する情報がない週でも、それらしい文章が出てくる。これは指示文に「該当なしの場合は『なし』とだけ書く」と明記して解決しました。AIは基本的に「何か書こう」とするので、書かない条件を明示的に与える必要があります。

- [ ] フィルタ条件は差出人ドメインを軸にした（件名キーワード頼りにしていない）
- [ ] メルマガ系は受信トレイをスキップする設定にした

- [ ] 「該当がなければ『なし』と書く」を禁止事項に明記した
- [ ] 設定内容と指示文をNotion等に全文保存し、変更履歴の欄を作った
- [ ] 1週間動かしてみて、出力を見ながら条件を1つだけ調整した

## この仕組みが解決する実務の課題

中小企業の現場でよく聞くのが「情報は届いているのに、整理されていないから使えない」という状態です。メールも社内連絡も業界情報も、量は十分あるのに、拾い上げる時間がない。

今回の仕組みは、そこに対する小さな答えです。AIに判断を丸投げするのではなく、**機械的に絞り込める部分はメールソフトの機能で処理し、まとめと提案の部分だけAIに任せる**。この役割分担なら、特別なシステム導入もコストもなしに、個人レベルで今日から始められます。

そして何より、この構築過程で「自分は毎週どういう基準で仕事を選別しているのか」が言語化されました。これは属人化した業務を他の人に引き継ぐときの、そのまま手順書になります。

## まとめ

- AIの出力が安定しないときは、指示文より先に入力データ（受信箱）を整える。
- 分類は細かくせず、維持できる粒度（5つ程度）から始めて運用しながら足す。
- 設定と指示文は全文保存しておく。2週間後の自分が必ず助かります。
