# ウェアラブルAIは「議事録」目的で選ぶと失敗する — Mori / PLAUD / Omi を比較してMoriを買った理由

会話を自動で録音・文字起こししてくれる「ウェアラブルAI」を検討している方向けの記事です。私は製造業の現場で働きながらAIコンサル・研修を副業でやっていますが、3機種（Mori / PLAUD / Omi）を比較する過程で「自分の目的を誤解していた」ことに気づき、評価軸がまるごと入れ替わりました。その経緯をそのまま記録します（購入はしましたが、届くのは11月末予定。実使用の検証はまだできていません）。

## そもそも、なぜウェアラブルAIを検討したのか

きっかけは単純で、「話したことが残らない」問題です。

- 現場で交わした立ち話の申し送りが、数日後には誰も正確に思い出せない
- 研修やコンサルの場で出た相談内容を、後でブログや資料の素材にしたいが手元にメモが残らない
- 移動中や作業中に思いついたことが、机に戻るまでに消える

最初はこれを全部ひとまとめに「議事録が欲しい」と表現していました。ここが後で引っかかるポイントになります。

なお、ウェアラブルAIとは、首から下げたりクリップで留めたりして常時身につけ、会話を自動で録音・文字起こし・要約してくれる小型デバイスのことです。スマホの録音アプリを「取り出して押す」手間をなくす、という位置づけの製品群です。

## 3機種をどう比べたか

比較した3つは、ざっくり性格が違います。

| 製品 | 私が受け取った性格 |
|---|---|
| PLAUD | 会議・商談の記録に強い。録音した内容を整った議事録・要約に落とすことが主眼 |
| Omi | 常時装着型。生活まるごとを拾いにいく思想が強い |
| Mori | 日々の発話をジャーナリング（日記・内省の記録）として溜めていく方向 |

最初に作った比較表の項目は、こんなものでした。

1. 文字起こしの精度
2. 話者分離（誰が話したかの区別）ができるか
3. 要約の質・フォーマットの整い方
4. 連続録音時間・バッテリー
5. 価格、サブスクの有無
6. 日本語対応

この軸で並べると、評価は素直にPLAUDに寄ります。「議事録が欲しい」という前提に対して、議事録を作ることに最適化された製品が一番になるのは当然です。

## 評価軸が入れ替わった瞬間

引っかかったのは、比較表を眺めながら「で、自分はその議事録を何に使うのか」と書き出したときでした。

改めて用途を分解すると、こうなりました。

- **社内会議の議事録** → 実はそこまで必要としていない。決定事項は結局その場でホワイトボードと写真で済ませている
- **顧客との商談記録** → 相手の同意が必要な場面が多く、常時装着で気軽に録るものではない
- **自分がひとりで喋った内容・現場での気づき・研修後の振り返り** → **これが圧倒的に多い**

つまり私が欲しかったのは「複数人の会話を整った文書にする機能」ではなく、**自分の思考のかけらを取りこぼさずに溜めておく箱**でした。目的を「議事録」から「素材の蓄積」に言い換えた時点で、評価軸は次のように差し替わりました。

1. **話者分離の重要度 → 下がる**（ほぼ自分ひとりなので区別の必要が薄い）
2. **要約フォーマットの整い方 → 下がる**（整った議事録より、生の言い回しが残るほうが素材として価値がある）
3. **装着の心理的ハードル → 最重要に浮上**（つけっぱなしにできるか。気になって外すなら意味がない）
4. **後から検索・掘り返せるか → 重要に浮上**（溜めたものを使えるかどうかは検索性で決まる）
5. **蓄積が長期で意味を持つ設計になっているか → 重要に浮上**

この並べ替えで、Mori のジャーナリング寄りの思想が自分の用途と噛み合っていると判断し、Mori を購入しました。PLAUD が劣っていたという話ではなく、**私の用途が議事録ではなかった**という話です。

## つまずいた点と解決

### つまずき1：やりたいことを最初から「機能名」で言ってしまった

「議事録が欲しい」は、実は**やりたいこと（目的）ではなく、解決策の名前**です。目的を解決策の名前で語ってしまうと、比較表の項目もその解決策に引っ張られ、「議事録を上手に作る製品はどれか」というズレた問いを解き続けることになります。

**解決策**：比較表を作る前に、「この道具を使う具体的な場面」を箇条書きで10個ほど書き出しました。場面ベースで書くと、自分のケースでは「複数人の会議」がほとんど出てこないことが数として見え、「議事録」という言葉が実態と合っていないと気づけました。

### つまずき2：スペック表の項目を無批判に信じた

メーカーが並べている比較項目（精度、話者分離、要約テンプレートなど）は、**その製品が勝てる軸**で作られています。それをそのまま自分の比較表に転記すると、メーカーの土俵で選ぶことになります。

**解決策**：項目を自分で書き直し、**各項目の横に「これが自分の何を良くするのか」を一文添える**ルールにしました。一文が書けない項目は、自分にとっては評価軸ではないので削りました。話者分離はこれで落ちました。

### つまずき3：「機能が多いほう」に流されかけた

Omi のように生活まるごとを拾う方向は魅力的ですが、自分の場合は拾った後の運用（どこに溜めて、どう見返すか）を決めていませんでした。運用が決まっていない状態で取得量を増やすと、見返さないデータが増えるだけです。

**解決策**：「溜めたものを週1回見返す時間が自分のスケジュールに取れるか」を先に確認しました。ここが現実的に取れる範囲で、装着ハードルと検索性を優先する判断に落としました。

## この判断が実務のどんな課題を解決するか

この記事の本題は製品選びそのものより、**「目的を言い換えると評価軸が入れ替わる」**という点です。これは中小企業のAI導入検討で、そのまま効く考え方だと感じています。

現場でよく見るのが、こういうパターンです。

- 「議事録を自動化したい」→ 実際の困りごとは「決まったことが現場に伝わっていない」
- 「チャットボットを入れたい」→ 実際の困りごとは「同じ問い合わせが特定の1人に集中している」
- 「AIで日報を要約したい」→ 実際の困りごとは「日報を誰も読んでいない」

最初の言い方でツール比較を始めると、比較表は埋まるのに導入後に使われない、という結果になりがちです。**言い換えを1回はさむだけで、必要な機能とそうでない機能がはっきり分かれます**。今回の私の場合、「議事録」→「素材の蓄積」と言い換えたら、最重要だった話者分離が不要項目に落ちました。これは比較表を作り直さないと絶対に見えなかった部分です。

## 明日から使えるチェックリスト

AIツール・デバイスを比較検討する前に、この順でやってみてください。

1. **使う場面を10個、具体的に書き出す**（「○月○日、△△で、□□をしていたとき」の粒度で）
2. 書き出した場面を数える。**多い場面が本当の用途**です。当初の言い方とズレていないか確認する
3. **やりたいことを「機能名」ではなく「困っている状態」で言い直す**（例：「議事録が欲しい」→「話したことが数日で消える」）
4. 言い直した表現をもとに、**評価軸を自分の言葉で書き直す**
5. 各評価軸の横に「これが自分の何を良くするのか」を一文書く。**書けない軸は削る**
6. **取得・生成した後の運用（どこに溜め、いつ見返すか）を先に決める**。決まらないなら取得量の多い製品は選ばない
7. 比較表の1位が変わったかを確認する。**変わったなら、最初の問いが間違っていた証拠**です
8. 導入後に検証する項目を、購入前に2〜3個メモしておく

## まとめ

ウェアラブルAIを「議事録」目的で比較するとPLAUDが強く、「素材の蓄積」に言い換えるとMoriが浮上しました。評価軸が入れ替わったのは製品ではなく、私の目的の言い方が変わったからです。実機は11月末到着予定なので、実使用の検証結果は改めて追記します。
